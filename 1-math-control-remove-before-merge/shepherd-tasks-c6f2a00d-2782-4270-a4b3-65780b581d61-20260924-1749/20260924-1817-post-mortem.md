## Section 7: Failure Analysis

There was no campaign-level or task-level failure. All four CLI result records have exit code `0`; no CCA, CCRA, CI, test, idle-kill, or timeout failure determined an outcome.

Two recoverable command-construction errors appeared in stage-30 sessions:

1. During [#2](https://github.com/edburns/dd-3068633-linux-x64-04/issues/2), the first attempt to read campaign metadata used `gh api ... -f ref=...` without forcing `GET`. GitHub returned HTTP 404 and `base64` reported invalid input. The next command explicitly used `--method GET`, retrieved the metadata, and validation continued.
2. During feedback inspection for both [#4](https://github.com/edburns/dd-3068633-linux-x64-04/pull/4) and [#5](https://github.com/edburns/dd-3068633-linux-x64-04/pull/5), `gh pr view` was called with incompatible `--comments` and `--json` flags. Each session retried with `--json comments`, confirmed no bot comments, and continued.

These errors added tool calls but did not alter code, skip a gate, or affect the final result. The `assistant.idle` event at the end of each JSONL session is a normal terminal session event, not evidence of an idle timeout.

## Section 8: Observations and Recommendations

### 8.1 What Worked Well

- **Serial dependency enforcement was correct.** [#3](https://github.com/edburns/dd-3068633-linux-x64-04/issues/3) used the merge of [#4](https://github.com/edburns/dd-3068633-linux-x64-04/pull/4) as its base and preserved the Fibonacci contract.
- **Exact-HEAD validation was strong.** Stage 30 ran the repository-owned acceptance command in detached worktrees and separately verified SHA-bound check runs.
- **Review request handling was deterministic.** Stage 40 required positive request acknowledgement and matched each CCRA review to the current HEAD.
- **Scope remained tight.** Both PRs changed only the implementation and test files allowed by their issues.
- **First-round convergence was complete.** Both CCRA reviews returned zero findings, requiring no local remediation commits.
- **Control semantics were preserved.** Lesson propagation remained `off`, and `campaign-lessons.md` stayed at its initial “no validated lessons” state.

### 8.2 What Could Be Improved

- The metadata-read and comment-inspection command errors were avoidable and duplicated known `gh` CLI edge cases.
- Post-mortem extraction requires reconstructing key outcomes from verbose Markdown transcripts. The stage artifacts do not provide one compact per-task outcome record.
- Aggregate token counts are unavailable because usage checkpoint token values are redacted. This limits comparison with earlier post-mortems that reported input/output tokens.
- AIU is observable, but the artifacts do not document a billing-credit or monetary conversion, and remote CCA/CCRA consumption is not separated from local CLI telemetry.

### 8.3 Recommendations

1. Make campaign metadata reads explicitly use `gh api --method GET` whenever `-f ref=...` is supplied.
2. Standardize bot-comment inspection on `gh pr view --json comments`; never combine `--comments` with `--json`.
3. Emit a compact stage outcome JSON record containing issue, PR, validated HEAD, phase timestamps, gate command/result, test count, CI count, CCRA review ID, comment count, merge commit, and final status.
4. Export non-sensitive aggregate input/output token counts in the session result even when prompt-cache details remain redacted.
5. Preserve the current exact-HEAD local-test, SHA-bound CI, acknowledged-review, unresolved-thread, and stable-HEAD merge gates; they produced clean first-round convergence in this run.
6. Keep lesson-mode reporting mandatory in future post-mortems so this `off` control can be compared directly with treatment campaigns using `campaign`.
